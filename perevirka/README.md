# Перевірка застосунку

Тут лежать скрипти, які **ганяють справжній застосунок** у браузері й звіряють
числа. Це не «подивитись очима» — кожен файл сам каже `ok` або `ПРОБЛЕМА`.

## Як запустити

```
cd perevirka
node audit.js        # 14 перевірок: екрани, періоди, пальне, валюти, оренда, фонд
node audit2.js       # 15 перевірок: заправки, знижки, ціль, фонд, мапа, чат
node life.js         # склад дня: додав / видалив зміну, замовлення
node life2.js        # місяць, заправки, сховище
node life3.js        # бак, рівень, балон, папка, фонд, оренда, податки разом
node organism.js     # чи сходяться «Бак», «Сервіс» і статистика між собою
```

Решта — вужчі: `swipe*.js` (проведення пальцем), `chat*.js` (підтримка),
`pause4.js` (пауза), `shots.js` (знімки), `close3.js` (завершення зміни),
`stats-bug.js` (фантомний пробіг), `refuel2.js` (сума замість літрів,
замовлення на баку, одометр).

Потрібен playwright і Chromium — вони вже стоять у робочій теці сесії.

## Правило

**Ніякої правки в розрахунках без прогону `life*.js` і `organism.js`.**
Вони ловлять саме те, що очима не видно: коли одна цифра змінилась, а
пов'язана з нею — ні.

### Що лишилось на потім

- **Файли SQL, які власник ще не виконував** — перевірити, що виконані:
  «Корона у водія», «Не рахувати себе у статистиці», «Зараз на зміні — по-чесному»,
  «Валюти водіїв у панелі», «Хто не вписав свої цифри», «Чат — чи дійшло в бот»,
  «Відповіді з бота» (виконувати двічі).
- **Перевірити на живому боті**, що повідомлення водія з бота доходить у переписку.
- Знімки зі старих звернень не відкриваються — їхні посилання підписані на
  10 хвилин і давно протермінувались. Нові підписуються надовго.
- «Де дешевше» лишається прибраним, поки чеків від водіїв замало.
